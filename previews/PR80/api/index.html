RandomizedTukeyHSD.RandomizedTukeyHSD — Module
RandomizedTukeyHSD

The randomized Tukey HSD test for comparing many treatments (systems, models, methods) over a shared set of blocks (topics, datasets, folds).

using Random, RandomizedTukeyHSD

problem = RandomizedTukeyProblem(responses; treatments=["A", "B", "C"])
results = solve(problem, FixedTrials(10_000); rng=Xoshiro(1))

responses has blocks in rows and treatments in columns. results has one named tuple per pair of treatments, with the fields treatment1, treatment2, mean1, mean2, difference and pvalue.

See RandomizedTukeyProblem, FixedTrials and solve to start, and the documentation at https://jerome-white.github.io/RandomizedTukeyHSD.jl for the rest.

RandomizedTukeyHSD.Checkpoint — Type
Checkpoint

What a monitor is shown at a checkpoint of a run, with fields

  • trials: the number of trials done so far;
  • planned: the number of trials the rule plans;
  • pvalues: a MonteCarloPValue for every pair of treatments, in the order of the results of solve!;
  • done: true at the last checkpoint, where trials == planned.

The checkpoint is a copy: it holds no reference to the run, so a monitor can look at it and keep it, and cannot change the run or its results.

RandomizedTukeyHSD.FixedTrials — Type
FixedTrials(trials)

The rule that runs exactly trials trials. In each trial the responses are shuffled across treatments within every block, and the largest minus the smallest treatment mean is recorded.

Throws an ArgumentError if trials is not positive.

RandomizedTukeyHSD.HDIWidth — Type
HDIWidth(width; level=0.95, prior=(1, 1))

A precision target: the highest density interval hdi reports for a p-value, with the same level and prior, is at most width wide.

The width depends on the number of trials that reach the observed difference, which is not known before the run. trials_for takes the number to expect if the exact p-value is p, that is trials * p, and looks for the least number of trials whose interval is no wider than width. For many trials this is close to StandardError at width / 3.92 (for level=0.95), since the posterior is then nearly normal; the two differ in what they say, not in the count.

Throws an ArgumentError if width is not positive, level is not between 0 and 1 or prior is not two positive numbers.

RandomizedTukeyHSD.LogMonitor — Type
LogMonitor()

A monitor that emits a log record at every checkpoint, at level LogLevel(-1): below Info, so the default logger shows nothing. To see the records, use a logger whose minimum level is lower, or one that renders progress (the level and the progress key are the convention of ProgressLogging.jl, which TerminalLoggers.jl and the VS Code and Pluto interfaces show as a progress bar):

using Logging
with_logger(ConsoleLogger(stderr, LogLevel(-1))) do
    solve(problem, FixedTrials(100_000); monitor=LogMonitor())
end

A record has the message "Randomized Tukey HSD" and the keys trials, planned, pvalues (the vector of the Checkpoint) and progress (the fraction done, and "done" at the end), and the record's id is how a progress display tells the records of one run from another's, so make a new LogMonitor for every run.

The records carry the p-values, not their intervals: call hdi or probability_below on them if you want those.

RandomizedTukeyHSD.MonteCarloPValue — Type
MonteCarloPValue(exceeding, trials)
MonteCarloPValue(pvalue, trials)

A Monte Carlo p-value that keeps what it was estimated from: exceeding of trials trials reached the observed difference. The p-value is exceeding / trials, and with the count kept, its Monte Carlo error can be described (see hdi and probability_below) without being passed trials again.

The first form takes the count, an Integer. The second takes a result's pvalue, an AbstractFloat, and recovers the count from it; the two are told apart by type, so MonteCarloPValue(1, 100) is one trial out of 100 and MonteCarloPValue(1.0, 100) is all of them.

float(p) and pvalue(p) give exceeding / trials.

Throws an ArgumentError if trials is not positive, if exceeding is not between 0 and trials, or if pvalue is not between 0 and 1 and a multiple of 1 / trials.

Example

problem = RandomizedTukeyProblem(responses)
results = solve(problem, FixedTrials(10_000))
p = MonteCarloPValue(results[1].pvalue, 10_000)

RandomizedTukeyHSD.RandomizedTukeyProblem — Type
RandomizedTukeyProblem(responses; treatments=axes(responses, 2))
RandomizedTukeyProblem(table; block, treatment, response)

The data a randomized Tukey HSD test is run on, to be solved with solve and a rule such as FixedTrials. A problem says what is tested and nothing about how: the number of trials and the random number generator come in at solve.

The first form takes responses, a blocks x treatments matrix of real numbers, and treatments, one name per column.

The second takes a Tables.jl table, such as a DataFrame, so that the names of the treatments come with the data. The shape is told by which of block, treatment and response are given; each is the name of a column, as a Symbol or a String.

  • Wide, with none given: each column is a treatment and each row a block. The treatments are named by the column names, as Symbols, as the table gives them. Pass only block to leave out a column that identifies the rows.
  • Tidy, with all three given: one row per block and treatment, with the block in column block, the treatment in treatment and the response in response. The treatments are named by the values of the treatment column, and blocks and treatments are taken in the order they first appear.

For a table, a missing response, and a pair of block and treatment with no row, become NaN and are rejected like any other NaN. A matrix with real elements takes the first form; a matrix of any other element type is rejected as a table.

Throws an ArgumentError if there are fewer than two treatments, if responses contains NaN (one NaN makes every p-value meaningless, including those of pairs that do not involve its treatment), if table is not a table, if a column does not exist, or if the roles are given partly; and a DimensionMismatch if treatments does not have one name per column.

Example

responses = [0.10 0.40 0.70; 0.20 0.50 0.60; 0.15 0.45 0.80; 0.25 0.35 0.65]
problem = RandomizedTukeyProblem(responses; treatments=["A", "B", "C"])

table = (block=["b1", "b1", "b2", "b2", "b3", "b3"],
         treatment=["A", "B", "A", "B", "A", "B"],
         response=[0.1, 0.4, 0.2, 0.5, 0.15, 0.45])
problem = RandomizedTukeyProblem(table; block=:block, treatment=:treatment,
                                 response=:response)

RandomizedTukeyHSD.RandomizedTukeyRun — Type
RandomizedTukeyRun

A RandomizedTukeyProblem being solved with a rule: what init returns, step! advances and solve! finishes.

Besides the problem, the rule and the generator, a run keeps what the trials so far have shown, so that nothing but counts is stored: for every pair of treatments, the number of trials whose range reached the pair's observed absolute difference in means. trials says how many trials that is out of, and pvalues turns the counts into MonteCarloPValues.

Every trial has its own random stream, which depends on a base seed drawn from the generator when the run is made and on the number of the trial. So the trials do not depend on how they are cut into chunks, which only says how step! schedules them, nor on the number of threads.

source
RandomizedTukeyHSD.StandardError — Type
StandardError(se)

A precision target: the Monte Carlo standard error of a p-value is at most se. A p-value estimated from trials trials has standard error sqrt(p * (1 - p) / trials) for an exact p-value p. This is the standard deviation of a binomial proportion, and holds without assuming a normal distribution; the normal distribution only comes in if the error is turned into an interval.

For trials_for that is p * (1 - p) / se^2 trials, rounded up: 250000 for se=0.001 in the worst case. (Floating-point error can make it one more than the exact count: 0.1 * 0.9 / 0.01^2 is 900.0000000000001, which rounds up to 901.)

Throws an ArgumentError if se is not positive.

CommonSolve.init — Method
init(problem::RandomizedTukeyProblem, rule;
     rng=Random.default_rng(), monitor=NoMonitor(), every=nothing)

Prepare to solve problem with rule (for now FixedTrials), drawing the trials from rng. Returns a RandomizedTukeyRun with no trials done, for step! or solve!.

One base seed is drawn from rng here and nothing is drawn later, so rng has advanced by the time init returns, whatever step! does.

monitor is shown a Checkpoint by solve! every every trials (rounded up to whole chunks of 64) and at the end; see emit for what a monitor is. Without every, the checkpoints are about 1% of the rule's trials apart. With the default NoMonitor there is no checkpoint but the last, and solve! runs all its trials in one go. The monitor and every change nothing in the results.

Throws an ArgumentError if every is not positive.

CommonSolve.solve! — Method
solve!(run::RandomizedTukeyRun)
solve(problem::RandomizedTukeyProblem, rule; rng=Random.default_rng())

Randomized Tukey HSD test over all pairs of treatments: step! until the rule is done, then report. solve is solve!(init(problem, rule; rng)).

A pair's p-value is the fraction of trials whose range is at least the pair's observed absolute difference in means. A p-value of 0 means no trial reached the difference, that is, p < 1/trials. rng is the random number generator the trials are drawn from (the global one if left out). With the same rng state, trials, responses and Julia version the p-values are the same at any number of threads.

Returns one named tuple per pair of treatments, in the order (1,2), (1,3), ..., (n-1,n), with fields treatment1, treatment2, mean1, mean2, difference (mean1 - mean2) and pvalue. A vector of named tuples is a Tables.jl table. To have the p-values with the number of trials they come from, see pvalues.

Example

using Random
responses = [0.10 0.40 0.70; 0.20 0.50 0.60; 0.15 0.45 0.80; 0.25 0.35 0.65]
problem = RandomizedTukeyProblem(responses; treatments=["A", "B", "C"])
results = solve(problem, FixedTrials(10_000); rng=Xoshiro(1))
results[2].pvalue   # A against C

CommonSolve.step! — Function
step!(run::RandomizedTukeyRun, nchunks=1)

Advance run by nchunks chunks of trials (64 trials each, but for the last chunk of the rule), in parallel on the available threads. Returns run.

The counts do not depend on the order the chunks finish in, so they do not depend on the number of threads either: adding whole numbers is exact.

Throws an ArgumentError if nchunks is not positive or is more than the rule has left.

source
RandomizedTukeyHSD.emit — Function
emit(monitor, checkpoint::Checkpoint)

The method a monitor defines. solve! calls it with a Checkpoint every every trials (see init) and once more at the end of the run, from the main task and between steps: a monitor need not be thread-safe, and the results of the run do not depend on what it does. The return value is ignored. A monitor may throw, which stops the run.

A monitor is any type with this method:

struct Print end
RandomizedTukeyHSD.emit(::Print, checkpoint) = println(checkpoint.trials)

solve(problem, FixedTrials(10_000); monitor=Print())

Whatever it does with the checkpoint (print, plot, send to a logger) is its own business. It is called at every checkpoint, so a monitor that wants fewer records keeps its own count.

RandomizedTukeyHSD.hdi — Method
hdi(p::MonteCarloPValue; level=0.95, prior=(1, 1))

Interval for the exact permutation p-value that p estimates, as a tuple (lower, upper): the highest density interval of its posterior distribution, which is the shortest interval holding probability level. Read it as "given these trials and the prior, the exact p-value is in the interval with probability level".

The exceeding trials out of trials are binomial in the exact p-value. A prior of (a, b) is a Beta(a, b) distribution for it, and the posterior is then Beta(a + exceeding, b + trials - exceeding). The default (1, 1) is the uniform distribution on [0, 1]; (0.5, 0.5) is Jeffreys' prior. The prior matters only for small counts. Both numbers must be positive.

This is a Bayesian credible interval, not a confidence interval, and has no coverage guarantee. When the posterior density is highest at 0 (as with no trial reaching the difference) or at 1, the interval is one-sided and runs from 0, or to 1. It describes the Monte Carlo error only: not the assumptions of the test, floating-point ties, or that many pairs are tested.

Throws an ArgumentError if level is not between 0 and 1 or prior is not two positive numbers.

Example

hdi(MonteCarloPValue(490, 10_000))               # about (0.0449, 0.0533)
hdi(MonteCarloPValue(0, 1_000))                  # about (0, 0.003)
hdi(MonteCarloPValue(490, 10_000); level=0.9)
hdi(MonteCarloPValue(490, 10_000); prior=(0.5, 0.5))

RandomizedTukeyHSD.probability_below — Method
probability_below(p::MonteCarloPValue, alpha; prior=(1, 1))

Probability that the exact permutation p-value that p estimates is below alpha, under the same posterior as hdi. It answers whether more trials could take the p-value across alpha; it is not a test, and alpha is the caller's.

Throws an ArgumentError if alpha is not between 0 and 1 or prior is not two positive numbers.

Example

probability_below(MonteCarloPValue(49, 1_000), 0.05)        # about 0.52
probability_below(MonteCarloPValue(4_900, 100_000), 0.05)   # about 0.93

pvalues(run::RandomizedTukeyRun)

RandomizedTukeyHSD.tidy_matrix — Method
tidy_matrix(blocks, treatments, responses)

Arrange tidy rows, one per block and treatment, into a blocks x treatments matrix of Float64. The three vectors have the same length: row i says that treatment treatments[i] had response responses[i] in block blocks[i].

Returns the matrix and the treatment names, one per column. Blocks and treatments are in the order they first appear. A pair that has no row, and a missing response, become NaN, which the test rejects.

Throws a DimensionMismatch if the vectors differ in length and an ArgumentError if a block and treatment pair appears more than once.

RandomizedTukeyHSD.trials_for — Method
trials_for(target; p=0.5)

Number of trials that meet a precision target, if the exact permutation p-value is p. A target is a StandardError or an HDIWidth; the answer is the smallest number of trials that meets it, to give to FixedTrials.

The precision of a p-value depends on the p-value, which is not known before the run. The default, p=0.5, is the worst case: no p-value is estimated less precisely, so the target is met for every pair. A p near the level you will judge the pairs at (say 0.05) needs fewer trials, and meets the target for p-values near it. p must be strictly between 0 and 1.

The target is a choice made before the run, from the precision wanted and not from the results. A pilot run to find p is possible (pass its p-value), but its trials are not part of the final run.

Throws an ArgumentError if p is not strictly between 0 and 1, or if the target needs more trials than a run can count.

Example

trials_for(StandardError(0.001))                 # 250000
trials_for(StandardError(0.001); p=0.05)         # 47500
trials_for(HDIWidth(0.002); p=0.05)

solve(problem, FixedTrials(trials_for(HDIWidth(0.002); p=0.05)))

Defining a target

A new kind of target is a type with a method trials_for(target, p) that returns the number of trials, an Int, for the exact p-value p.

RandomizedTukeyHSD.wide_matrix — Method
wide_matrix(names, columns)

Arrange a wide table, one column of responses per treatment, into a blocks x treatments matrix of Float64, one row per row of the table. names are the treatment names and columns the columns, in the same order. A missing response becomes NaN, which the test rejects.
