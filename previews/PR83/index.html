RandomizedTukeyHSD.jl

A Julia implementation of the randomized Tukey HSD test for comparing many treatments (systems, models, methods) over a shared set of blocks (topics, datasets, folds). The method is described by Carterette (2012) and advocated by Sakai (2018).

The test needs no normality assumption. In each of trials trials the responses are shuffled across treatments within every block, and the largest minus the smallest treatment mean is recorded. A pair's p-value is the fraction of trials whose range is at least the pair's observed difference. It is not corrected by adding one to the count, so a p-value of 0 means p < 1/trials.

Status

Pre-release (0.1.0-DEV), not yet in the General registry.

Installing

using Pkg
Pkg.add(url="https://github.com/jerome-white/RandomizedTukeyHSD.jl")

The library needs Julia 1.10 or newer and depends only on CommonSolve, Logging, Random, SpecialFunctions, StatsAPI and Tables.

A first example

The data are a matrix with blocks in rows and treatments in columns: here four blocks and three treatments. The names of the parts are in the Glossary.

using Random, RandomizedTukeyHSD

responses = [0.10 0.40 0.70
             0.20 0.50 0.60
             0.15 0.45 0.80
             0.25 0.35 0.65]

problem = RandomizedTukeyProblem(responses; treatments=["A", "B", "C"])
results = solve(problem, FixedTrials(10_000); rng=Xoshiro(1))
3-element Vector{@NamedTuple{treatment1::String, treatment2::String, mean1::Float64, mean2::Float64, difference::Float64, pvalue::Float64}}:
 (treatment1 = "A", treatment2 = "B", mean1 = 0.17500000000000002, mean2 = 0.42500000000000004, difference = -0.25, pvalue = 0.3925)
 (treatment1 = "A", treatment2 = "C", mean1 = 0.17500000000000002, mean2 = 0.6874999999999999, difference = -0.5124999999999998, pvalue = 0.0037)
 (treatment1 = "B", treatment2 = "C", mean1 = 0.42500000000000004, mean2 = 0.6874999999999999, difference = -0.26249999999999984, pvalue = 0.3886)

results has one named tuple per pair of treatments, in the order (1,2), (1,3), ..., (n-1,n), with the fields treatment1, treatment2, mean1, mean2, difference (mean1 - mean2) and pvalue. A vector of named tuples is a Tables.jl table, so DataFrame(results) and CSV.write(io, results) work without this package depending on either.

for r in results
    println(r.treatment1, " vs ", r.treatment2, ": p = ", r.pvalue)
end
A vs B: p = 0.3925
A vs C: p = 0.0037
B vs C: p = 0.3886

The interface

The interface is that of CommonSolve.jl, the one the SciML packages share: a problem says what is solved, a rule says how, and solve(problem, rule) is solve!(init(problem, rule)). The verbs init, solve, solve! and step! are re-exported (see the API reference), and they are the same functions, so there is no clash with another package that uses them.

  • RandomizedTukeyProblem(responses; treatments): the data. responses has blocks in rows and treatments in columns, at least two columns and no NaN (see Missing responses). treatments is one name per column and defaults to the column numbers. A problem is checked when it is built, so an invalid one cannot exist.
  • FixedTrials(trials): the rule, the number of trials (called B in the literature and in earlier versions of this package).
  • rng: optional keyword of solve and init, a random number generator (see Threads and reproducibility).

Citing

To cite the package, use "Cite this repository" on the GitHub page, which reads its CITATION.cff. Please also cite the sources of the method:

  • Carterette, B. A. (2012). Multiple testing in statistical analysis of systems-based information retrieval experiments. ACM Transactions on Information Systems, 30(1), 1-34. doi:10.1145/2094072.2094076
  • Sakai, T. (2018). Multiple Comparison Procedures. In Laboratory Experiments in Information Retrieval (The Information Retrieval Series, pp. 59-80). Springer Singapore. doi:10.1007/978-981-13-1199-4_4
