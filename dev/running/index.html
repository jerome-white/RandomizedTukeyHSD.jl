Stepping and watching a run

Stepping a run

solve runs the whole rule. To look at a run on the way, make it with init, advance it with step! (in chunks of 64 trials, on all the threads), and read it with trials and pvalues:

using Random, RandomizedTukeyHSD

responses = [0.10 0.40 0.70
             0.20 0.50 0.60
             0.15 0.45 0.80
             0.25 0.35 0.65]
problem = RandomizedTukeyProblem(responses; treatments=["A", "B", "C"])

run = init(problem, FixedTrials(10_000); rng=Xoshiro(1))
step!(run, 10)    # ten chunks, 640 trials
trials(run)       # 640
640
pvalues(run)      # a MonteCarloPValue for each pair, out of 640 trials
3-element Vector{MonteCarloPValue}:
 MonteCarloPValue(239, 640)
 MonteCarloPValue(3, 640)
 MonteCarloPValue(237, 640)
solve!(run)       # the rest, then the results, as for `solve`
3-element Vector{@NamedTuple{treatment1::String, treatment2::String, mean1::Float64, mean2::Float64, difference::Float64, pvalue::Float64}}:
 (treatment1 = "A", treatment2 = "B", mean1 = 0.17500000000000002, mean2 = 0.42500000000000004, difference = -0.25, pvalue = 0.3925)
 (treatment1 = "A", treatment2 = "C", mean1 = 0.17500000000000002, mean2 = 0.6874999999999999, difference = -0.5124999999999998, pvalue = 0.0037)
 (treatment1 = "B", treatment2 = "C", mean1 = 0.42500000000000004, mean2 = 0.6874999999999999, difference = -0.26249999999999984, pvalue = 0.3886)

The run keeps one count per pair, not the trials, so its memory does not grow with the number of trials, and however the chunks are cut into steps the counts are the same as with one solve. A step past the trials the rule plans throws an ArgumentError.

Watching a run

A monitor is shown the p-values so far at regular checkpoints, so you can watch the Monte Carlo settle. It only looks: it gets a copy, not the run, so it cannot change the p-values or stop the run (stopping is a rule decided beforehand, not something to do when an estimate looks good, which biases the decision). The default monitor, NoMonitor, does nothing.

using Logging
with_logger(ConsoleLogger(stderr, LogLevel(-1))) do
    solve(problem, FixedTrials(100_000); monitor=LogMonitor(), every=10_000)
end

LogMonitor emits a Logging record at every checkpoint, at level LogLevel(-1), which the default logger does not show; the call above lowers the level to print them. Loggers that draw progress bars (TerminalLoggers, the VS Code and Pluto interfaces) show the progress key of the records as a bar. A record carries trials, planned, the pvalues (a MonteCarloPValue per pair, for which hdi and probability_below give the uncertainty) and progress. every is the number of trials between checkpoints, rounded up to whole chunks of 64, and defaults to 1% of the trials.

To send the numbers somewhere else, write a monitor: a type with a method of emit, called at every checkpoint with a Checkpoint (trials, planned, pvalues, done).

struct Trace
    trials::Vector{Int}
    smallest::Vector{Float64}
end
Trace() = Trace(Int[], Float64[])

function RandomizedTukeyHSD.emit(trace::Trace, checkpoint)
    push!(trace.trials, checkpoint.trials)
    push!(trace.smallest, minimum(pvalue.(checkpoint.pvalues)))
end

trace = Trace()
solve(problem, FixedTrials(1_000); rng=Xoshiro(1), monitor=trace, every=256)
trace.trials
4-element Vector{Int64}:
  256
  512
  768
 1000

Monitors are called from the main task between steps, so they need not be thread-safe, and the results are the same with or without one.
